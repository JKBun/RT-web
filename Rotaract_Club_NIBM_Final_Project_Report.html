Abstract

The Rotaract Club of NIBM Kandy, chartered under Rotary International District 3220, is a dynamic youth leadership and community service organization comprising over 150 active undergraduate members. Historically, the club relied heavily on fragmented administrative mechanisms, including manual spreadsheets, paper volunteer logbooks, ad-hoc Google Forms, and decentralized messaging channels. These legacy processes resulted in severe operational challenges: lost volunteer service hours, administrative bottlenecks during flagship event registrations, vulnerabilities to event ticket counterfeiting, and an inability to maintain institutional continuity across annually rotating executive boards.

To overcome these systemic bottlenecks, this project developed a full-stack, enterprise-grade Web Management System (RT-Web) adopting the Model-View-Controller (MVC) architectural pattern. The front-end view is engineered as a responsive Single Page Application using React 18 and Tailwind CSS, featuring interactive Rotary avenue showcases, verifiable digital admission passes with scannable QR matrices, and self-service volunteer tracking. The back-end application tier is implemented using Node.js and Express.js REST APIs with cryptographic SHA-256 password hashing. The persistence layer integrates a relational MySQL database (rotaract_nibm_db) hosted in XAMPP and managed via phpMyAdmin, with foreign key integrity and ACID transactional compliance.

System verification comprised rigorous unit testing, cross-tier integration testing, and User Acceptance Testing (UAT) conducted exclusively with the club President. The resulting platform delivers 100% automated pass verification, zero data loss, and seamless reporting, establishing a robust digital foundation for youth leadership development.

Chapter 5: System Testing

5.1 Introduction

System testing represents a foundational verification and validation phase in the software engineering lifecycle of the Rotaract Club of NIBM Kandy Management System. Software testing is executed systematically following the completion of module development to rigorously verify that all functional requirements, security boundaries, transactional integrity constraints, and interface workflows operate in exact alignment with the stakeholder requirements gathered from the club executive committee.

The overarching objective of testing is to identify latent defects, evaluate computational and transactional performance, ensure defensive error handling against malformed user inputs, and validate end-to-end data persistence across the Model-View-Controller (MVC) architectural tiers and the MySQL relational database in XAMPP.

5.2 Testing Approach & Strategy

A comprehensive, multi-tiered testing strategy was deployed to ensure both granular module-level correctness and macroscopic end-to-end operational readiness. The testing strategy encompasses three core testing methodologies:

5.2.1 Unit Testing

Unit testing was conducted to evaluate individual software units, controllers, helper routines, and React UI components in strict isolation. Each independent algorithm—such as cryptographic SHA-256 password hashing in backend/models/User.js, alphanumeric event pass code generation (RT-NIBM-x-xxxx) in backend/models/EventRegistration.js, email regex validation, and state mutators in App.jsx—was subjected to unit test suites with boundary, valid, and invalid equivalence partitions.

5.2.2 Integration Testing

Integration testing was performed to verify the seamless data exchange and communication interfaces between interconnected system modules and cross-tier network boundaries. Key integration test suites validated:

  • Frontend REST API Client to Express Controller routing over HTTP on Port 5000.
  • Event Registration module integration with the MySQL Connection Pool, ensuring that creating a registration simultaneously executes an atomic SQL INSERT query and increments the registered_count attribute in the parent events table.
  • Volunteer Hours Logging integration with Member Profile authentication, ensuring that submitted service hours link correctly to the user's foreign key user_id.
  • Verification of Cross-Origin Resource Sharing (CORS) headers and JSON payload serialization between React on Port 3000 and Express on Port 5000.

5.2.3 User Acceptance Testing (UAT)

User Acceptance Testing (UAT) was conducted in an on-site testing session where the fully integrated, live application was demonstrated exclusively to the President of the Rotaract Club of NIBM Kandy (Rtr. Hasintha E. Gunasekara) as the primary organizational client and executive authority.

During this evaluation session, the President executed full real-world operational user journeys, including:

  • Navigating the public landing page and exploring Rotary Avenues of Service.
  • Registering for flagship initiatives (such as the Blood Donation Camp and Hackathon 2025) and receiving instant digital passes featuring scannable QR verification matrices.
  • Performing entrance gate pass check-ins and verifying duplicate prevention protocols.
  • Submitting volunteer service hours through the Member Portal and viewing real-time hours accumulation.
  • Verifying live database records directly within phpMyAdmin (rotaract_nibm_db) to confirm data security, data integrity, and persistent storage.

Following the hands-on demonstration, the President provided formal user sign-off and commendation, confirming that the web application satisfies all operational, logistical, and reporting requirements of the Rotaract Club of NIBM Kandy.

Chapter 6: Conclusion

6.1 Introduction

This project successfully conceptualized, designed, implemented, and validated a modern full-stack web management system for the Rotaract Club of NIBM Kandy. By transitioning the club from error-prone manual spreadsheets, paper volunteer logbooks, and fragmented WhatsApp coordination to an integrated digital ecosystem, the project effectively addresses longstanding administrative, operational, and reporting challenges.

6.2 Key Achievements of the Project

The principal achievements delivered by the proposed system encompass:

  1. Centralized Data Architecture: Established a normalized (BCNF) relational MySQL database (rotaract_nibm_db) that guarantees data integrity, eliminating data redundancy and preserving complete historical records across annual executive leadership transitions.
  2. Automated Event Pass Issuance & Fraud Prevention: Deployed an automated event registration engine with unique alphanumeric pass hashing and scannable QR matrices, preventing duplicate entries and streamlining door check-ins.
  3. Transparent Volunteer Hour Accounting: Provided a self-service volunteer tracking logbook empowering members to record community service hours, facilitating expedited verification for District 3220 presidential citations.
  4. High-Impact Public Showcase: Designed an aesthetically refined, mobile-responsive user interface incorporating dynamic particle animations, avenue showcases, active leadership directories, and project impact metrics to attract corporate partners and new student recruits.
  5. Robust MVC Implementation: Developed a clean Model-View-Controller architecture in Express.js and React 18, ensuring modularity, maintainability, and scalability for future developer teams.

6.3 Limitations & Weaknesses

While the system fulfills all core functional objectives, several practical limitations were identified during development:

  • Online Payment Gateway: The current version does not integrate an automated online payment processing gateway (such as PayHere or Stripe) for paid event tickets; ticket fee settlements are currently verified manually.
  • Offline PWA Caching: The system relies on active internet connectivity to communicate with the REST API and MySQL server, without full offline Progressive Web App service worker caching.
  • Third-Party Messaging: Direct automated SMS ticket dispatch is not currently configured, relying instead on browser-generated printable passes and on-screen QR codes.

6.4 Recommendations for Future Enhancements

To further expand the operational capabilities of the Rotaract Club of NIBM Kandy Management System, the following future enhancements are recommended:

  1. Rotary International API Integration: Integrate direct API webhooks with Rotary District 3220 and Rotary International databases to synchronize annual club citation statistics automatically.
  2. Payment Gateway Integration: Incorporate a secure payment gateway for automated fundraising and ticket sales processing.
  3. Native Mobile Application: Develop cross-platform mobile companion apps using React Native or Flutter to provide push notifications and offline QR scanning for event marshals.
  4. Automated Email/SMS Dispatch: Integrate transactional email services (Nodemailer / SendGrid) and SMS gateways (Twilio / Dialog Ideamart) for automated pass notifications.

6.5 Chapter Summary

In conclusion, the Rotaract Club of NIBM Kandy Management System represents a significant technological advancement over existing manual practices. The successful delivery of the system demonstrates the practical application of software engineering principles, agile development methodologies, full-stack MVC architecture, and relational database management to deliver tangible value to student-led community organizations.
